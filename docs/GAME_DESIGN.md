# Project Automata --- GAME_DESIGN

**Status:** Game Design candidate for Design Gate\
**Date:** 2026-08-14\
**Working title:** Project Automata\
**Phase owner:** Game Designer

> This document consolidates the Game Design decisions developed after
> the approved Project Brief. Major project approval remains owned by
> the Orchestrator / Producer.

------------------------------------------------------------------------

## 1. High Concept

Project Automata is a mobile Idle / Incremental game built around a
transformation of player role:

**Manual → Assisted → Automated → Optimized → Autonomous**

The player begins by personally operating a primitive production
machine. Over time, they construct machinery, automation systems,
robots, AI-controlled industry, megafactories, orbital infrastructure,
planetary industry, stellar industry, and eventually a Dyson Swarm-scale
civilization.

The central fantasy is:

> **"At the beginning, I do everything myself. At the end, I have built
> a gigantic system that works for me."**

The factory is visually represented and visibly evolves, but Project
Automata is **not** a free-form factory-building simulation. Production
is mathematical; conveyors, resources, robots and machinery visualize
that economy without becoming an authoritative physical simulation.

------------------------------------------------------------------------

## 2. Game Pillars

### 2.1 Automation is progression

Automation is not cosmetic. Each major step should reduce old manual
work and move the player toward higher-level decisions.

### 2.2 Automate labor, not decisions

The factory may work without the player.

It must not intelligently progress through the game without the player.

The player remains responsible for meaningful decisions such as: -
investment; - major unlocks; - breakthroughs; - era transitions; -
prestige; - permanent upgrades; - later strategic systems.

### 2.3 Visible growth

Economic progress must produce visible factory progress.

The player should be able to compare the beginning and current state of
a run and immediately perceive growth.

### 2.4 Constant acceleration

Previously difficult goals become trivial through upgrades and prestige.
Old eras become increasingly fast while the frontier of progression
moves forward.

### 2.5 Controlled scope

Depth should come from combinations of simple, reusable, data-driven
systems rather than simulation complexity or large quantities of bespoke
mechanics.

------------------------------------------------------------------------

## 3. Core Loop

The high-level loop is:

**Produce → Improve → Automate → Expand → Optimize → Reach New Era →
Reboot → Accelerate**

More explicitly:

1.  perform or observe production;
2.  gain the primary run resource;
3.  buy producer levels;
4.  reach milestones;
5.  unlock meaningful breakthroughs;
6.  automate previously manual work;
7.  unlock a new producer;
8.  visibly expand the factory;
9.  reach a new technological era;
10. eventually Reboot Civilization;
11. spend permanent AI Cores;
12. replay previous progression dramatically faster;
13. push farther than the previous civilization.

### Player-role evolution

Early game: - player performs production.

Early-mid game: - player launches or assists production batches.

Mid game: - robots execute production automatically.

Later: - new industrial systems are inherently automated.

The important constraint is that removing operational labor must create
room for progression decisions rather than remove the reason to play.

------------------------------------------------------------------------

## 4. Core Resources

### 4.1 Primary run resource

**Working name: Industrial Output**

One main spendable run resource drives: - producer purchases; - producer
levels; - automation; - breakthroughs; - progression toward new
production tiers.

Exact name and economic formulas remain Economy Design responsibilities.

### 4.2 Thematic production concepts

Parts, Modules and Robots may appear visually or as progression counters
without becoming independent spendable currencies.

The game should avoid a large collection of resource wallets unless a
new resource creates a meaningful new decision.

### 4.3 Permanent resource

**AI Cores**

AI Cores are earned through Reboot Civilization and survive resets.

They fund permanent progression.

Whether AI Cores interact with IAP is explicitly unresolved and belongs
to Economy & Monetization Design.

------------------------------------------------------------------------

## 5. Producers

The production chain should be thematically coherent while remaining
economically abstract.

The player sees the impression of:

**components → assemblies → robots → autonomous production**

without requiring authoritative inventories or physical material
routing.

### MVP producer structure

#### 1. Fabricator

**Era:** Manual Workshop

Purpose: - introduces production; - starts manually; - establishes
action → output → upgrade.

Progression: - manual cycles; - levels; - milestones; - Auto Feeder
breakthrough; - becomes fully automatic.

Visual: - primitive fabrication/press machine; - later gains
feeder/conveyor/automation modules.

#### 2. Assembly Station

**Era:** Manual Workshop

Purpose: - introduces the idea of a production chain; - moves
interaction from continuous manual work to assisted batches.

Progression: - player initially launches production batches; - first
Worker Bot automates the station.

Visual: - receives components from the Fabricator through decorative
logistics; - first robot is produced/introduced around this stage.

#### 3. Robot Line

**Era:** Automated Factory

Purpose: - turns robots from an automation reward into a visible output
of the industrial system.

Robots should support milestones and unlocks rather than require worker
assignment micromanagement.

#### 4. Automated Cell

**Era:** Automated Factory

Purpose: - demonstrates technological advancement by arriving largely or
fully automated; - marks the transition from "automate each primitive
task" to "build systems designed for automation."

Visual: - robotic arms; - enclosed machinery; - stronger
conveyor/logistics activity; - more autonomous visual behavior.

#### 5. Advanced Robotics Complex

**Working name. Era:** Robotics Complex

Purpose: - end-of-MVP macro producer; - represents industrial-scale
robotic manufacturing; - pushes toward AI Megafactory.

Final naming belongs to later design/art consolidation.

------------------------------------------------------------------------

## 6. Robots

Robots are a central fantasy and visual milestone.

They should **not** require individual assignment or complex worker
management in the MVP.

Possible uses: - automate Assembly; - unlock robotic infrastructure; -
satisfy cumulative milestones; - unlock Automated Cell; - provide global
progression thresholds.

Examples: - first robot: major onboarding event; - 10 robots:
milestone; - 100 robots: milestone; - later quantities: increasingly
large-scale industrial progression.

**First Robot** receives exceptional presentation on the first
civilization.

------------------------------------------------------------------------

## 7. Upgrade Structure

Use three layers.

### 7.1 Levels

Frequent purchases.

Purpose: - continuous incremental growth; - primary resource sink; -
frequent player decisions.

Support bulk purchasing: - ×1; - ×10; - ×MAX.

### 7.2 Milestones

Threshold rewards at selected producer levels.

Potential effects: - production multiplier; - visual tier; - unlock
requirement; - progression bonus.

Exact thresholds and values are Economy Design responsibilities.

A reusable conceptual structure is preferred, e.g. milestones around
several recognizable level thresholds rather than bespoke rules for
every producer.

### 7.3 Breakthroughs

Rare, meaningful upgrades that visibly or mechanically change
progression.

MVP examples: - Auto Feeder; - Worker Bot; - Robotic Logistics; -
Automated Cell; - Factory Control System; - Advanced Robotics; -
Civilization Reboot.

Breakthroughs should feel qualitatively more important than normal
percentage upgrades.

------------------------------------------------------------------------

## 8. Automation Progression

Automation evolves rather than repeating the same "buy manager"
interaction forever.

### Stage I --- Manual

The player performs production cycles.

### Stage II --- Assisted

The player launches batches or occasionally intervenes.

### Stage III --- Automated

Robots and machinery perform recurring operations.

### Stage IV --- Self-Automating

Advanced production systems are designed to function autonomously once
built.

### Stage V --- Optimized

AI-era systems optimize large-scale industry while the player makes
strategic choices.

### Stage VI --- Autonomous

The industrial civilization operates at massive scale without
operational input.

**Critical rule:** autonomous production does not mean autonomous
progression.

------------------------------------------------------------------------

## 9. First 15 Minutes

Timings are design targets, not final economy values.

### 0:00--0:30 --- Learn by doing

Scene: - almost-empty Manual Workshop; - one Fabricator; - clear
interaction affordance.

Player: - taps Fabricator; - sees machine cycle; - gains first
Industrial Output; - buys first upgrade.

Learning objective: - operate machine; - earn; - improve machine.

Avoid long tutorial text.

### 0:30--2:00 --- First acceleration

Player: - continues manual production; - buys several upgrades; - sees
increasing output.

A clear goal appears:

**Automate Fabricator**

Progress toward its cost is always visible.

### \~2:00 --- First Automation

Player unlocks Auto Feeder.

Presentation: - module installs; - conveyor/feeder activates; - machine
starts cycling without taps; - "AUTOMATED" feedback.

This is one of the most important onboarding payoffs.

### 2:00--5:00 --- Worker to manager

Player: - watches automatic production; - invests earnings; - sees the
next empty production slot.

Target: **Assembly Station**

### \~4:00--5:00 --- Assembly Station

The station is visibly constructed.

Camera/environment subtly expands.

The factory now reads as a chain rather than a single machine.

### 5:00--8:00 --- Assisted production

Assembly uses batch-style interaction rather than returning to frantic
tapping.

The player's previous task remains solved; intervention has moved
farther down the chain.

### \~7:00--8:00 --- First Robot

Player builds the first Worker Bot.

Presentation should be unusually strong.

The robot visibly joins the factory and automates Assembly.

The player now owns a small autonomous industrial system.

### 8:00--12:00 --- Optimization

Player learns: - producer levels; - milestones; - saving versus
spending; - production acceleration.

Do not introduce unnecessary additional systems.

### \~10:00 --- Foreshadowing

The next major industrial slot/system becomes visible before it is
affordable.

### 12:00--15:00 --- First economic choice

Player chooses between: - upgrading current production; - saving for the
next major unlock.

### \~15:00 --- Robotics frontier

Target outcome: - Robotics content is unlocked or immediately within
reach; - workshop has transformed into a visibly automated line; - at
least one robot is active; - production is dramatically above the first
manual cycle.

------------------------------------------------------------------------

## 10. Era Structure

Full long-term direction:

### Era 1 --- Manual Workshop

Scale: - individual machines.

Main feeling: - "I am building my first machines."

Introduces: - manual production; - levels; - milestones; - first
automation; - first robot.

First-run target duration: - minutes, roughly 15--30 minutes pending
Economy Design.

### Era 2 --- Automated Factory

Scale: - production line / factory floor.

Main feeling: - "I own a real factory."

Introduces: - larger producer chain; - global factory improvements; -
stronger upgrade-vs-unlock decisions; - Robot Line and Automated Cell.

### Era 3 --- Robotics Complex

Scale: - industrial robotics complex.

Main feeling: - "My factory builds its own workers."

Introduces: - robot milestones; - large-scale robotic automation; -
first prestige frontier.

### Era 4 --- AI Megafactory

Scale: - intelligent megafactory.

Main feeling: - "I direct an industrial intelligence."

Potential future mechanic: - AI strategy/optimization choices.

This mechanic is **not required for the MVP**.

### Era 5 --- Orbital Industry

Scale: - orbital infrastructure.

Main feeling: - "Industry is no longer confined to the planet."

Potential interaction: - large launch/construction milestones.

### Era 6 --- Planetary Industry

Scale: - planets/sites as macro producers.

Main feeling: - "I industrialize worlds."

Prefer **Planetary Industry** over the earlier working name Planetary
Mining because the fantasy should exceed extraction alone.

### Era 7 --- Stellar Industry

Scale: - interplanetary / stellar infrastructure.

Main feeling: - "I command an industrial civilization across a star
system."

### Era 8 --- Dyson Swarm

Scale: - stellar megastructure.

Main feeling: - culmination of the automation fantasy.

A Dyson Swarm is preferred conceptually because thousands/millions of
elements can appear progressively, creating an incremental visual
endgame.

### Scale evolution

The meaning of "producer" evolves:

**Machine → Production Line → Factory → Megafactory → Orbital Facility →
Planet → Stellar Structure**

The underlying mathematical producer architecture can remain similar
while perceived scale increases dramatically.

------------------------------------------------------------------------

## 11. Era Pacing Intent

Do not finalize exact timing before Economy Design.

Intended progression scale:

-   Workshop: minutes;
-   Automated Factory: first hour;
-   Robotics: first hours;
-   AI: first day / early days;
-   Space: within a reasonable multi-day horizon;
-   Planetary/Stellar: longer-term progression;
-   Dyson Swarm: aspirational endgame.

Space must not arrive immediately, but it must also not be hidden behind
months of play because Automation → Robotics → AI → Space is part of the
product promise.

------------------------------------------------------------------------

## 12. Prestige --- Reboot Civilization

### Purpose

Prestige converts the limits of one civilization into permanent
acceleration for the next.

Fantasy:

> The previous civilization compresses its technological knowledge into
> AI Cores. The next civilization inherits that intelligence.

### First availability

Target: - around late Robotics Complex; - after several hours of
cumulative first-run progression, subject to Economy balancing.

### Reset

A Reboot resets substantial run progress: - Industrial Output; -
producer levels; - producer unlocks; - run breakthroughs; - robot run
counts where appropriate; - current era progression; - temporary run
upgrades.

### Retained

The player keeps: - AI Cores; - permanent AI Core upgrades; -
achievements/meta records; - highest-era/lifetime statistics where
implemented; - premium/IAP ownership.

### Permanent upgrade directions

Keep the MVP meta compact.

Three conceptual branches:

#### Production

Increase industrial power.

#### Automation

Make old manual/assisted phases faster to eliminate.

#### Expansion

Accelerate progress toward major unlocks/new eras.

MVP target: - approximately 6--9 meaningful permanent upgrades total; -
avoid a large prestige tree.

### Prestige decision

The Reboot UI should show: - AI Cores earned now; - progress toward the
next Core; - concrete preview of permanent benefits.

Prestige remains player-triggered.

Never Reboot automatically offline.

### Growth Runs vs Push Runs

Prestige naturally creates two play patterns:

**Growth Run** - Reboot relatively early; - farm permanent progression.

**Push Run** - remain in current civilization; - reach a new era or
record; - earn a larger future prestige reward.

This creates strategy without a new subsystem.

### Civilization numbering

Display: - Civilization #1; - Civilization #2; - etc.

The Workshop after a Reboot should contain at least a subtle persistent
visual sign of inherited AI technology so that permanent progression is
tangible.

------------------------------------------------------------------------

## 13. Offline Progression

### Core rule

Only production that has been automated continues offline.

This makes automation valuable beyond convenience.

### Availability

Offline production naturally begins when the player's first production
system becomes automated.

No separate late-game offline unlock is required.

### Return flow

Show a short **Factory Report**:

-   time away;
-   Industrial Output generated;
-   Collect.

Avoid excessive statistics.

After collection, immediately surface what the reward enables or
advances.

Example: **ROBOTICS COMPLEX READY**

### Design requirement

A meaningful return should normally: - enable useful purchases; -
trigger/reach a milestone; - significantly approach a breakthrough; - or
materially advance the next goal.

Returning after hours away should not feel economically irrelevant.

### Offline cap

Use a cap.

Exact duration and upgrade interactions belong to Economy Design.

Potential permanent upgrades may extend offline capacity.

### Offline restrictions

Offline systems may produce resources.

They must not autonomously: - Reboot; - choose permanent upgrades; -
trigger major era transitions; - choose AI strategy; - make major
progression decisions.

------------------------------------------------------------------------

## 14. Session Structure

Project Automata should support multiple natural session lengths.

### Micro-session --- 1--3 minutes

-   open;
-   collect offline;
-   buy upgrades;
-   hit a milestone if available;
-   close.

### Medium session --- 5--15 minutes

-   collect;
-   optimize;
-   unlock producer/breakthrough;
-   observe factory transformation;
-   pursue next goal.

### Long session --- 20--40+ minutes

Typically around: - Reboot; - rapid early civilization replay; - new
era; - push run; - major discovery.

The player should never be punished for closing the game.

------------------------------------------------------------------------

## 15. Active Interaction --- Overclock

**MVP candidate accepted as Free Overclock.**

Purpose: - preserve an optional active interaction after routine
production is automated; - reinforce factory spectacle without
reintroducing tapping chores.

Concept: - player activates Overclock; - factory enters a short
temporary accelerated state; - production visibly increases; -
machinery, robots, effects and audio intensify; - cooldown follows.

MVP: - free Overclock only; - simple timer + cooldown; - no energy
system; - no minigame; - no tap spam.

Rewarded Overclock can later be evaluated by Monetization Design.

------------------------------------------------------------------------

## 16. Retention Structure

MVP retention should primarily be intrinsic to progression.

Core reasons to return: - automated offline earnings; - visible next
unlock; - producer progression; - robot milestones; - factory
evolution; - new eras; - Reboot; - permanent acceleration; -
anticipation of AI/space escalation.

Avoid relying on checklist retention systems before the core loop is
validated.

### Next Goal

MVP requirement.

Always expose one clear structural goal, e.g.: - Automate Fabricator; -
Build Assembly Station; - Build First Robot; - Unlock Robot Line; -
Reach Robotics Complex; - Reboot Civilization.

This is not a quest system.

It is a direct representation of the core progression data.

The player should usually see one future item beyond the current goal,
but the full eight-era roadmap should not be exposed immediately.

Discovery should make the game feel progressively larger.

------------------------------------------------------------------------

## 17. Feedback Hierarchy

Feedback intensity should match event importance.

### Level purchase --- light

-   instant number change;
-   small sound;
-   subtle machine pulse;
-   production/s updates.

No popup.

### Milestone --- medium

-   short flash;
-   multiplier/result displayed;
-   stronger sound;
-   optional visual module/tier change.

No blocking dialog.

### Breakthrough / Automation --- strong

-   2--4 second transformation;
-   module installation;
-   robot/conveyor activation;
-   clear state change.

### New Producer --- very strong

-   visible construction in the previously foreshadowed slot;
-   activation sequence;
-   camera framing;
-   first production cycle.

### Era Transition --- exceptional

-   controlled camera change;
-   environment expansion/replacement;
-   strong sense of increased scale.

### Reboot --- exceptional/meta

-   civilization knowledge converges into AI Core;
-   factory powers down;
-   transition;
-   Civilization #N appears;
-   new Workshop begins immediately.

The player should return to interaction without unnecessary intermediate
screens.

------------------------------------------------------------------------

## 18. Special First-Time Events

### First Automation

One of the most important moments in the game.

It marks the moment the game visibly becomes idle.

Give it stronger treatment than later automation unlocks.

### First Robot

Major first-run event and marketing-relevant payoff.

Give it an animation/presentation close to an era-level event the first
time only.

Later robots become routine output and should not interrupt play.

------------------------------------------------------------------------

## 19. Factory Visual Progression Requirements

The factory is the primary visual progress bar.

The player should see:

**empty workshop → production chain → automated factory → robotics
complex → megafactory → orbital industry → planetary industry → stellar
industry → Dyson Swarm**

### Controlled layouts

No free camera-dependent construction gameplay.

Use predetermined layouts.

Camera may: - pan; - recenter; - zoom/dezoom; - reveal new controlled
areas.

The player should not need to search a map for important producers.

### Economic vs visual speed

Economic cycles and visual animation frequency remain decoupled.

Visual activity can use bounded states such as: - idle; - slow; -
active; - fast; - overclocked.

This prevents huge economic multipliers from requiring impossible
animation rates.

### Modular asset evolution

Prefer: - base machine; - upgrade module; - automation module; -
effects; - robots.

Avoid requiring unique art for every economic level.

------------------------------------------------------------------------

## 20. Core HUD Requirements

Keep the primary screen readable.

Always visible or immediately accessible: - Industrial Output; -
Production / second; - AI Cores after prestige unlock; - factory
scene; - selected producer controls; - level/buy controls; - relevant
automation/breakthrough; - Next Goal.

Avoid turning the main screen into an analytics dashboard.

Use compact large-number notation such as: - 1K; - 1M; - 1B; - 1T.

Exact notation beyond MVP ranges belongs to Economy/Technical Design.

------------------------------------------------------------------------

## 21. Pacing Rules

### Early game

Target: - interesting event approximately every 30 seconds to 3 minutes.

### First hour

Target: - meaningful event approximately every 3--10 minutes.

### Later

Small milestones remain regular while major unlocks become progressively
farther apart.

Distinguish: - interesting event; - major event; - exceptional event.

### Dead-zone rule

If a playtester spends several minutes: - without a meaningful
decision; - without a nearby visible unlock; - and without useful
interaction,

mark the segment as a **DEAD ZONE**.

First attempt to solve dead zones through: - costs; - production
rates; - milestone placement; - unlock pacing; - Overclock
availability; - offline progression.

Do **not** automatically add a new feature or minigame.

------------------------------------------------------------------------

## 22. MVP Scope

The gameplay MVP validates:

1.  core incremental satisfaction;
2.  visible automation payoff;
3.  manual → automated transition;
4.  anticipation between unlocks;
5.  first prestige/restart;
6.  desire to return for offline production.

### MVP eras

Complete: 1. Manual Workshop 2. Automated Factory 3. Robotics Complex

Tease only: 4. AI Megafactory

Space remains future-facing content.

### MVP content target

-   manual production;
-   one primary run resource;
-   AI Cores as prestige resource;
-   5 producers;
-   producer levels;
-   producer milestones;
-   approximately 6--8 meaningful breakthroughs;
-   visible automation;
-   visible robots;
-   three complete eras;
-   factory visual evolution;
-   Next Goal;
-   Free Overclock;
-   offline progression;
-   Reboot Civilization;
-   Civilization numbering;
-   approximately 6--9 prestige upgrades;
-   AI Megafactory teaser;
-   controlled onboarding;
-   bulk upgrade purchase support.

### Monetization hooks in gameplay design

Natural future placements: - optional ×2 offline earnings; - optional

optional bonus reward.

Core gameplay MVP does not need full monetization integration to
validate fun.

No forced interstitial direction.

## 27. Dependencies for Economy Design

Economy Design must convert the pacing intentions into actual curves.

Required outputs include: - Industrial Output formulas; - producer costs
and rates; - milestone thresholds/effects; - breakthrough prices; - era
unlock requirements; - expected first-run timings; - expected
first-Reboot timing; - AI Core formula; - prestige upgrade
costs/effects; - offline production cap/formula; - Overclock
parameters; - Growth Run vs Push Run viability; - dead-zone analysis; -
F2P progression integrity; - rewarded-ad economic bounds.

Critical economy constraint:

> Offline returns and active progression must regularly create
> actionable decisions without making ads the dominant optimal strategy.

## 28. Dependencies for Art Direction

Art Direction must make progression readable without requiring
simulation complexity.

Required: - Manual Workshop look; - Automated Factory look; - Robotics
Complex look; - AI Megafactory teaser; - modular producer evolution; -
Auto Feeder; - Worker Bot; - Robot Line; - Automated Cell; - Advanced
Robotics Complex; - conveyors/arms/logistics decoration; - first
Automation presentation; - first Robot presentation; - era transition
language; - Reboot sequence; - AI Core visual; - Overclock state; - UI
hierarchy; - store screenshot hook.

Critical visual constraint:

> A screenshot of the early Workshop and a screenshot of Robotics
> Complex should immediately communicate dramatic progression.

------------------------------------------------------------------------

## 29. Dependencies for Technical Design

Technical Design should preserve the separation between mathematical
economy and visual representation.

Required technical domains: - generic producer system; - generic
level/milestone system; - breakthrough/unlock system; - automation state
system; - era progression; - Next Goal; - offline production; -
prestige/reset; - permanent upgrades; - Overclock; - save/load; -
deterministic data-driven content; - visual state binding; - bulk
purchase; - large-number support.

Do not implement authoritative physical production, pathfinding-heavy
robots or free-form construction.

The design is highly compatible with Codex because most gameplay can be
expressed through generic systems plus data.

------------------------------------------------------------------------

## 30. MVP Validation Criteria

The prototype should be reworked if the following fail:

### Comprehension

A new player should understand very quickly that they produce, improve
and automate.

### Automation payoff

The first automation should create obvious relief and power.

### Visual progression

Meaningful visual evolution must occur during the opening minutes.

### Anticipation

The player should almost always understand what they are working toward
next.

### Prestige

After the first Reboot, the second civilization should feel dramatically
faster and encourage continued play.

### Offline

Returning after absence should feel rewarding and create an immediate
decision.

### Scope

If solving a pacing issue appears to require adding an unrelated
subsystem, first re-evaluate the economy and existing milestone cadence.

# HANDOFF TO ORCHESTRATOR

## Concept final

Project Automata is a mobile Idle / Incremental centered on the fantasy
of **escaping manual labor by building increasingly autonomous
industry**.

The player begins by operating a single machine and eventually commands
industry at planetary and stellar scale.

The key design rule is:

**Automate labor, not decisions.**

## Core loop retained

**Produce → Improve → Automate → Expand → Optimize → New Era → Reboot →
Permanent Acceleration → Push farther**

Manual interaction intentionally declines as the player's industrial
civilization advances.

## Main decisions

-   Factory is visible and evolves continuously.
-   Factory layouts are predetermined; no free construction.
-   Economy remains mathematical and decoupled from visual
    conveyors/robots.
-   Production chain is thematically coherent without complex
    intermediate-resource simulation.
-   One primary run currency is preferred.
-   Robots are visible milestones/automation agents, not individually
    managed workers.
-   Upgrades use Levels + Milestones + Breakthroughs.
-   Old labor becomes automated; new progression decisions remain
    manual.
-   One clear Next Goal guides progression.
-   Free Overclock is retained as a simple optional active interaction
    in the MVP.
-   First Automation and First Robot receive exceptional presentation.

## Era structure

Long-term direction:

1.  Manual Workshop
2.  Automated Factory

## Automation

Progression:

**Manual → Assisted → Automated → Self-Automating → Optimized →
Autonomous**

Automation removes old chores but does not make strategic progression
decisions for the player.

## Prestige

Prestige fantasy:

**Reboot Civilization**

Permanent resource:

**AI Cores**

First prestige target: - around late Robotics Complex / several hours of
cumulative first-run progression, subject to Economy Design.

Reset is substantial.

AI Cores and permanent upgrades survive.

Permanent progression is organized around: - Production; - Automation; -
Expansion.

MVP target: - approximately 6--9 meaningful prestige upgrades.

Prestige should make previous eras dramatically faster.

The system naturally supports: - Growth Runs; - Push Runs.

## Offline progression

-   Automated production continues offline.
-   Non-automated production does not.
-   Offline starts naturally once first automation is unlocked.
-   Return flow uses a concise Factory Report.
-   Offline rewards should lead quickly to an actionable decision.
-   Major progression decisions never happen automatically offline.
-   Exact cap/formula belongs to Economy Design.

## Main design risks

1.  **Weak pacing** --- long dead zones can destroy retention.
2.  **Automation without gameplay** --- automation must remove chores,
    not player decisions.
3.  **Generic factory presentation** --- robot/automation identity and
    visible evolution must differentiate the game.
4.  **Prestige frustration** --- first Reboot must immediately
    demonstrate increased power.
5.  **Offline irrelevance** --- returning must create useful
    progression.
6.  **Scope creep** --- avoid solving pacing problems by adding
    unrelated systems.
7.  **Ad dependency** --- future rewarded ads must remain optional and
    bounded.
